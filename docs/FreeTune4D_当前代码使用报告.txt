FreeTune4D 当前代码使用报告

一、项目用途

FreeTune4D 用于四维磁共振成像（4D MRI）的运动重建。其目标是利用同一受试者的一组高空间质量三维 MRI（UQ-3D MRI）作为解剖先验，将空间质量较低但包含连续呼吸运动信息的动态四维 MRI（LQ-4D MRI）重建为兼具高空间质量和动态呼吸运动信息的 UQ-4D MRI。当前仓库中的临床处理脚本主要面向 T2 加权腹部 MRI 数据。

二、模型输入与输出

1. 输入数据

（1）动态 4D MRI DICOM 序列：提供不同呼吸时刻的运动信息。
（2）静态高质量 3D T2 MRI DICOM 序列：提供清晰的解剖结构先验。
（3）基础信息与路径参数：包括数据根目录、患者 MR 号、检查日期、3D 序列名称以及用于继承 DICOM 信息的参考文件。
（4）模型权重：粗尺度网络 coarse.h5 和精细尺度网络 fine.h5。

预处理程序首先读取原始 DICOM，将动态数据进行呼吸相位聚类、相位内平均、重采样和空间对齐，生成 phase_T2.mat。该文件包含 FourD_ave_save（整理后的 4D MRI）和 T2_save（对齐后的高质量 3D T2 MRI）。

2. 输出结果

主程序在 UQ_4D_T2 目录中输出每个呼吸相位的重建结果，包括 UQ_T2_<帧号>.mat 和 T2w_frame<帧号>_<层号>.dcm；同时保存相应的低质量 4D MRI DICOM 及可视化质控图。输出 DICOM 继承参考序列的像素间距、层厚、方向和患者信息，并重新生成相关 UID。当前代码将 frame_limit 设为 64，即粗级形变估计最多处理第 0 至第 64 帧。

三、算法流程与主要特点

1. 数据预处理与相位整理：预处理脚本读取动态 DICOM，通过图像相似性进行聚类，将原始动态帧整理为设定数量的呼吸相位；随后对 4D MRI 和 3D T2 MRI 进行等体素重采样、公共视野裁剪和空间对齐。

2. 参考相位选择：程序计算各 4D MRI 相位与高质量 3D T2 MRI 的全局相关系数，选择相关性最高的相位作为参考相位。代码中的变量名称虽然使用 SSIM_T2，但实际调用的是自定义相关系数函数 compute_cc，而不是结构相似性 SSIM。

3. 初始传统配准：高质量 3D T2 MRI 与选定的 4D 参考相位依次进行 Elastix 刚性配准和 B 样条非刚性配准，以校正扫描位置、姿态和初始结构差异。

4. 两级形变估计：当前代码构建两个 HyperVxmDense 网络。粗尺度网络输入尺寸为 128×128×128，编码和解码特征通道主要为 64；精细尺度网络输入尺寸为 224×224×224，特征通道主要为 24。两级网络均设置 5 个积分步。粗级网络先估计高质量 3D MRI 到各动态相位的主体形变，细级网络再估计残余形变，以进一步校正局部结构。

5. 时间维运动平滑：程序收集各呼吸相位的三维位移矢量场（DVF），对每个空间位置及每个位移方向沿时间轴进行三次 B 样条拟合，从而降低相邻相位间的突变，使呼吸运动更加连续。

6. 图像生成：经平滑的粗级形变和精细形变依次作用于高质量 3D T2 MRI，将其传播到全部呼吸相位，最终得到 UQ-4D MRI。

算法的主要特点是融合高质量解剖先验和低质量动态运动信息，采用粗到细的两级形变场兼顾大范围运动与局部细节，并通过时间平滑增强呼吸运动连续性。论文说明该方法部署到新中心时不要求基于梯度的微调或重新训练，可直接使用默认设置，或通过少量候选参数和无监督相似性指标选择结果。需要注意的是，严重扫描伪影、极低软组织对比度或椎体近乎不可见等极端情况可能降低重建效果。

四、论文精度与运行速度

论文采用椎体归一化互相关（NCC）、归一化互信息（NMI）、局部互相关（LCC），以及肝脏和脾脏的呼吸运动误差进行评价。NCC、NMI 和 LCC 越高越好，运动误差越低越好。这些结果属于多指标评价，不应被合并或表述为单一的“模型准确率”。

多中心外部验证中，FreeTune4D 的结果如下（均值±标准差）：

机构 B／T1 加权：椎体 NCC 0.313±0.068，NMI 0.365±0.072，LCC 0.126±0.014，肝脏运动误差 2.629±1.750 mm，脾脏运动误差 4.635±2.575 mm。

机构 B／T2 加权：椎体 NCC 0.265±0.024，NMI 0.345±0.044，LCC 0.128±0.030，肝脏运动误差 1.576±1.345 mm，脾脏运动误差 2.371±1.178 mm。

机构 C／T1 加权：椎体 NCC 0.305±0.048，NMI 0.388±0.051，LCC 0.072±0.018，肝脏运动误差 4.770±2.328 mm，脾脏运动误差 2.650±1.358 mm。

机构 A 的评估中，T1 加权任务结果为：椎体 NCC 0.469±0.039，NMI 0.411±0.053，LCC 0.158±0.031，肝脏运动误差 1.703±1.231 mm，脾脏运动误差 1.611±1.491 mm。T2 加权任务结果为：椎体 NCC 0.379±0.014，NMI 0.336±0.041，LCC 0.161±0.025，肝脏运动误差 3.560±2.441 mm，脾脏运动误差 2.868±2.279 mm。论文指出跨模态图像的对比度差异会降低相似性指标的绝对数值，因此上述结果更适合用于同一评价设置下的方法间相对比较。

速度方面，论文在机构 A 的 10 帧 T1 加权数据上报告 FreeTune4D 的平均重建时间为 911.2±156.3 ms／帧。该结果表明论文实验条件下可以实现亚秒级单帧重建，但该时间不包括所有数据准备、DICOM 读写和可视化开销，不能直接等同于当前完整脚本的端到端运行时间。

五、软件环境

仓库 requirements.txt 中的主要版本为：TensorFlow-GPU 2.10.0、TensorFlow Estimator 2.10.0、Keras 2.10.0、PyTorch 2.1.0+cu121、TorchVision 0.16.0、TorchAudio 2.1.0、VoxelMorph 0.2、NumPy 1.26.4、SciPy 1.13.1、SimpleITK 2.3.1、pydicom 2.4.4、scikit-image 0.24.0 和 nibabel 4.0.0。程序还调用外部 Elastix 工具完成初始刚性和 B 样条配准。

PyTorch 包中的 cu121 表示该 PyTorch 构建对应 CUDA 12.1。与此同时，仓库锁定 TensorFlow-GPU 2.10.0，但没有提供经过验证的 CUDA、cuDNN、显卡驱动和操作系统完整组合。因此不能仅凭 requirements.txt 断言 TensorFlow 2.10 与 PyTorch cu121 已在同一个 CUDA 环境中兼容运行。正式部署时建议使用项目已经验证的容器或环境；如无现成环境，应分别核对两个框架的兼容矩阵并完成端到端测试。

六、硬件配置、最低要求与模型参数量

论文进行运行时间测试时使用的工作站配置为 AMD EPYC 9654 CPU、NVIDIA RTX A6000 GPU 和 256 GB 系统内存。该配置只能称为“论文实测配置”，不能称为“最低运行配置”。

当前主程序将 PyTorch 设备直接设为 cuda，未实现纯 CPU 自动回退，因此按现有代码运行需要可用的 NVIDIA CUDA GPU。仓库和已提供的论文页面均未给出最低 GPU 型号、最低显存、最低 CPU 核数或最低系统内存，也没有提供不同硬件上的峰值资源占用。为避免无依据推测，本报告不自行给出最低配置数值。建议使用具有代表性的最大尺寸病例，记录粗级、细级推理及完整流程的峰值显存、峰值内存和端到端耗时，再逐级降低 GPU 显存和主机资源，以确定可复现的最低配置。

仓库没有包含 coarse.h5 和 fine.h5 权重文件，论文截图也没有给出参数量，所以目前无法可靠报告模型总参数量或权重大小。取得实际权重后，应在与部署一致的 VoxelMorph/TensorFlow 版本中分别构建两个模型，调用 model.count_params() 统计粗级和细级网络参数量，并报告两者之和，同时记录两个 H5 文件的实际磁盘大小。

七、运行方式与使用注意事项

首先执行预处理脚本，指定 phase_num、base_path、MR_number 和 st_date，生成 phase_T2.mat。随后运行 4DMRI Synthesis_UTSW_DVFsmooth_YP_T2_Steps.py，并指定 base_path、MR_number、st_date、name_3d、reference_file、net_path_coarse 和 net_path_fine。运行目录中还需要能够访问 Elastix 可执行文件及其参数文件。执行前应确认输入 DICOM 的像素间距、层厚、方向、切片顺序和动态时间点排列正确，并检查目标输出目录的磁盘空间。

当前代码包含固定的本地绝对路径、直接指定 cuda 设备、运行时生成随机 DICOM UID、较多逐帧质控图，以及 TensorFlow 与 PyTorch 混合使用等实现特点。在迁移到其他服务器前，应先替换固定路径、验证 GPU 环境、检查 DICOM 合规性，并在少量匿名化病例上完成结果与性能测试。该代码及论文结果目前应视为科研和部署评估依据；进入临床流程前仍需完成本地数据验证、质量控制、隐私保护及相应合规审查。
