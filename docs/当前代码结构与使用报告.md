# FreeTune4D 当前代码结构与使用报告

> **报告基线**：`main` 分支，基线提交 `22d1de2`。  
> **报告范围**：仓库当前可见的核心脚本、配置、第三方源码和依赖锁定文件。本文区分“代码已实现”“论文报告”和“当前仓库尚不能确认”三类信息，不把推测写成事实。

## 1. 项目概览

FreeTune4D 是一套腹部 4D MRI 运动重建流程。它以低空间质量动态 4D MRI（LQ-4D MRI）提供呼吸运动，以同一受试者的高质量静态 3D T2 MRI（UQ-3D MRI）提供解剖细节，通过预处理、传统配准、两级 HyperVxmDense 形变估计和时间维形变场平滑，生成逐呼吸相位的高质量 4D T2 MRI（UQ-4D MRI）。

当前代码不是一个安装后即可调用的 Python 包，而是由两个顺序执行的顶层脚本、共享工具模块、损失/指标模块、Elastix 配置和多个随仓库附带的第三方项目组成。核心使用路径为：

```text
原始 THRIVE 动态 DICOM + T2_AX_MVXD 静态 DICOM
    │
    ├─ 第 1 阶段：STEP_02_UTSW_ImageTest_YP_T2_Clinic_Amp_v2.py
    │    └─ phase_T2.mat + Full_data.mat + GIF/PNG/JPG 质控文件
    │
    └─ 第 2 阶段：4DMRI Synthesis_UTSW_DVFsmooth_YP_T2_Steps.py
         └─ UQ_4D_T2/*.mat + UQ/LQ DICOM + tmp_plot/*.jpg
```

## 3. 第 1 阶段：数据预处理的全部功能

入口：`STEP_02_UTSW_ImageTest_YP_T2_Clinic_Amp_v2.py`。

### 3.1 命令行参数

| 参数 | 类型/默认值 | 含义 |
|---|---|---|
| `--phase_num` | `int`, `5` | 输出呼吸相位数，同时是 KMeans 聚类数。 |
| `--base_path` | 开发机绝对路径 | 数据根目录；程序随后 `chdir` 到此目录。 |
| `--MR_number` | `raw` | 患者目录名/MR 号。 |
| `--st_date` | `StDate` | 检查日期目录名。 |

期望目录：

```text
<base_path>/
└── <MR_number>/
    └── <st_date>/
        ├── <名称包含 THRIVE 的目录>/
        │   └── IM-*.dcm
        └── <名称包含 T2_AX_MVXD 的目录>/
            └── IM-*.dcm
```

动态序列首个 DICOM 必须包含 `NumberOfTemporalPositions`。代码假设排序后的动态 DICOM 顺序是“每层内时间点连续”，并用 `slice = index // nTP`、`time = index % nTP` 组装 `(Rows, Columns, slices, time)` 数组。静态序列组装为 `(Rows, Columns, slices)`。

### 3.2 处理步骤

1. **DICOM 读取**：读取 `PixelSpacing`、`SliceThickness`、`ImagePositionPatient` 和像素数组；可选检查前三维尺寸。
2. **原始数据归档**：把完整动态数组保存为 `Full_data.mat`，变量名为 `FourD`。
3. **相位聚类**：
   - 全局 min-max 归一化所有帧；
   - 计算所有上三角帧对的局部 NCC，批量大小固定为 20，设备固定为 `cuda:0`；
   - 构造对称相似性矩阵并以 `KMeans(n_clusters=phase_num, random_state=0, n_init=10)` 聚类；
   - 根据类间平均相似性排序各簇，并从首尾簇选择代表性帧；
   - 保存 `clustering/matrix.npz` 和 `clustering/collected_4d.npz`。
4. **备用幅度分箱**：`BA_based_amplitude_sorting()` 可按冠状面 ROI 中超过阈值的体表面积进行呼吸幅度分箱，但当前主入口没有调用该函数，且主入口构造的 `opts` 不包含该函数要求的 ROI 坐标。
5. **GIF 输出**：保存原始动态中间冠状面 `4D_AX_T2.gif` 和聚类代表相位 `4D_AX_ave_T2.gif`。
6. **物理范围对齐**：依据 DICOM 位置和体素间距求 4D/T2 公共物理范围；对二者使用一阶插值进行等体素重采样和裁剪。
7. **平面内对齐**：将 T2 的 X/Y 尺寸中心裁剪或零填充到 4D 尺寸。
8. **轴向匹配**：使用 `peilin_loss.NCC` 搜索 Z 向偏移，只接受至少 50% 的重叠；先评估中心位置，再搜索所有候选，并保存匹配前后、绝对差和 LCC 曲线。
9. **最终裁剪**：各方向再去掉 1 体素边界；4D 相位数据转换为 `uint16`。
10. **最终输出**：保存 `phase_T2.mat`，变量为 `T2_save`、`FourD_ave_save`、`best_lcc`、`best_fd_start` 和 `best_t2_start`；保存所有仍打开的 Matplotlib 图及 `debug_vis/` 内容；创建空的 `UQ_4D_T2/` 目录供下一阶段使用。

## 4. 第 2 阶段：配准与 UQ-4D 合成的全部功能

入口：`4DMRI Synthesis_UTSW_DVFsmooth_YP_T2_Steps.py`。

### 4.1 命令行参数

| 参数 | 默认值/要求 |
|---|---|
| `--base_path` | 开发机绝对路径；必须改为数据根目录。 |
| `--MR_number` | 病例目录名。 |
| `--st_date` | 检查日期目录名。 |
| `--net_path_coarse` | 粗级 Keras H5 权重；仓库未提供。 |
| `--net_path_fine` | 细级 Keras H5 权重；仓库未提供。 |
| `--name_3d` | 静态 DICOM 目录名，默认 `T2_AX_MVXD`。 |
| `--reference_file` | 用作输出模板的 DICOM 文件名，默认 `IM-301-0001.dcm`。 |

### 4.2 模型配置

| 项目 | 粗级 | 细级 |
|---|---:|---:|
| 网络 | `vxm.networks.HyperVxmDense` | `vxm.networks.HyperVxmDense` |
| 输入大小 | `128×128×128` | `224×224×224` |
| U-Net 特征 | 编码 `[64]×4`；解码 `[64]×6` | 编码 `[24]×4`；解码 `[24]×6` |
| `int_steps` | 5 | 5 |
| `reg_field` | `warp` | `warp` |
| `int_resolution` / `svf_resolution` | 2 / 2 | 2 / 2 |
| 权重加载 | 按层名从 `coarse.h5` 加载 | 按层名从 `fine.h5` 加载 |

TensorFlow 模型固定使用 GPU `0`。PyTorch 张量和 `SpatialTransformer` 固定使用 `cuda`，没有 CPU 回退选项。仓库没有两个 H5 文件，因此当前无法核验权重结构、文件大小或总参数量；取得权重后，应在相同 `voxelmorph`/TensorFlow 版本中分别执行 `count_params()`。

### 4.3 处理步骤

1. 从 `<base>/<MR>/<date>/phase_T2.mat` 读取 `FourD_ave_save` 和 `T2_save`，从 `<name_3d>` 读取原始 T2 DICOM 头及空间位置。
2. 计算每个 4D 相位与 T2 的全局相关系数，选择最大者为参考相位。变量名 `SSIM_T2` 具有误导性：实际计算的是 `compute_cc()`，并非导入的 scikit-image SSIM。
3. 调用外部 `elastix`：先按 `parameters_Rigid.txt` 刚性配准，再按 `Par0020bspline2-MI-lesswarp.txt` 做 B 样条配准；中间 NIfTI 写到 `temp_folder_1/2`。
4. 建立原始 T2 尺寸的 PyTorch `SpatialTransformer`；把 T2 和参考相位归一化并三线性缩放到粗级尺寸。
5. 对每个相位调用 `peilin.inference_HyperMorph()`：在 0 到 1 间测试 11 个超参数，按 LCC 选择最佳值，然后输出三通道粗级 DVF。粗级循环受 `frame_limit=64` 限制。
6. `dvf_interp()` 对 DVF 三个方向分别做三线性插值，并按新旧尺寸比缩放位移幅值。
7. `DVF_smooth()` 对每个体素、每个位移维度沿相位轴做三次 B 样条拟合，平滑因子 `s=0.1`。
8. 把平滑粗级 DVF 作用到 T2；将结果和目标相位缩放到 `224³`，由细级模型估计残余 DVF，再次作用到图像。
9. 每个相位保存 `UQ_T2_<frame>.mat`，内含合成 UQ 图和插值后的原 LQ 图；向 `tmp_plot/` 写入原始、移动、固定、形变后图像以及三个 DVF 分量的大量 JPG。
10. 以参考 DICOM 为模板生成 UQ DICOM：像素负值截为 0，乘 500 后转 `uint16`，更新患者、UID、Series、Rows/Columns、层位置、方向、间距等字段，描述设为 `UQ-T2w 4D-MRI frame <frame>`。
11. 第二个输出循环把 LQ 相位插值回 DICOM 空间，以类似方法写出 `LQ_T2w_frame<frame>_<slice>.dcm`。

## 5. 公共模块功能

### 5.1 `peilin.py`

- `plot_3DLiver()`：输出轴位、冠状位和矢状位中间切面的三联 JPG。
- `inspect_weight_loading()`：读取 H5 的 `model_weights` 分组，比较模型层与权重层，按名称加载并打印匹配/缺失/多余层。
- `ObtainSubMatrixGlobal()`：按名称计算 LCC、SSIM、PSNR、NMI、MSE；ROIErr、CNR、FWHM 是空实现；代码引用的 PBM 在当前 `peilin_loss.py` 中不存在。
- `decide_hyp()`：在 `[0,1]` 上均匀取 11 个候选值，以 NCC 损失最小选择 HyperMorph 超参数。
- `inference_HyperMorph()`：转换 TensorFlow/PyTorch 的轴顺序、执行候选搜索和预测、返回 PyTorch 格式的 DVF。
- `inference_SynthMorphDDEM()` / `inference_SynthMorph()`：SynthMorph 推理辅助函数，当前主流程未调用。
- `load_dicom_4d()`：按 `T2w_frame{frame}_{slice}.dcm` 命名规则回读输出，返回 `[frame,slice,H,W]` 和头列表。

### 5.2 `peilin_loss.py`

| 实现 | 用途 |
|---|---|
| `NCC` | 局部归一化互相关损失；预处理聚类和轴向匹配使用。 |
| `MSE` | 均方误差。 |
| `Dice` | 分割重叠 Dice 损失。 |
| `Grad` | 2D/3D 位移场一阶差分平滑正则。 |
| `NMI` | 基于软直方图/核估计的归一化互信息。 |
| `PSNR` | 峰值信噪比。 |
| `SSIM` | 2D/3D 结构相似性。 |
| `jacobian_determinant_vxm` | VoxelMorph 风格位移场 Jacobian 行列式。 |
| `SDLogJ` | Jacobian 对数的标准差。 |
| `PercentJ` | 非正 Jacobian 体素比例。 |

### 6.2 CUDA、Python 与外部程序

- `torch==2.1.0+cu121` 表明记录的 PyTorch wheel 是 CUDA 12.1 构建。
- TensorFlow GPU 2.10.0 和 PyTorch cu121 是否能在同一套 CUDA/cuDNN 中工作，仓库没有给出已验证矩阵或容器，不能仅由依赖文件断言兼容。
- 仓库没有明确声明 Python 版本；存在 `cpython-39.pyc`，只能说明某次运行使用过 CPython 3.9，不能代替正式版本约束。
- 主脚本通过命令名 `elastix` 启动外部程序；仓库只附带 Windows 版 `elastix.exe`。Linux 服务器需要另行安装 Linux Elastix 并把它加入 `PATH`。
- 主脚本实例化 `oct2py.Oct2Py()`，所以即使当前有效配准函数直接用 subprocess，启动阶段仍要求系统可找到 GNU Octave。

### 6.3 为什么不能直接执行 `pip install -r requirements.txt`

依赖文件包含多条 `包名 @ file:///croot/...`、`file:///tmp/...` 和指向 `/usr/local/MATLAB/R2024a/...` 的本机路径。这些路径在另一台机器通常不存在。此外，PyTorch 的 `+cu121` wheel 往往需要正确的 wheel 源。建议以原开发环境导出可移植 Conda YAML 或构建 Docker 镜像，而不是把当前文件视为跨机器安装清单。

## 8. 论文精度、速度与硬件（不是当前仓库自动测试结果）

根据用户提供的 IEEE JBHI 作者版本页面（DOI `10.1109/JBHI.2026.3698133`）：

- 外部验证机构 B/T1-w：NCC `0.313±0.068`、NMI `0.365±0.072`、LCC `0.126±0.014`、肝/脾运动误差 `2.629±1.750 / 4.635±2.575 mm`。
- 外部验证机构 B/T2-w：NCC `0.265±0.024`、NMI `0.345±0.044`、LCC `0.128±0.030`、肝/脾误差 `1.576±1.345 / 2.371±1.178 mm`。
- 外部验证机构 C/T1-w：NCC `0.305±0.048`、NMI `0.388±0.051`、LCC `0.072±0.018`、肝/脾误差 `4.770±2.328 / 2.650±1.358 mm`。
- 论文报告 FreeTune4D 为 `911.2±156.3 ms/帧`，测试的是机构 A 的 10 帧 T1-w 数据；不能把该数字当成当前 Python 脚本含预处理、Elastix、绘图和 DICOM I/O 的端到端时间。
- 论文工作站为 AMD EPYC 9654、NVIDIA RTX A6000、256 GB 内存。这是论文实测配置，不是最低配置。

NCC/NMI/LCC 越高越好，运动误差越低越好；这些指标不能合并成单一“准确率”。仓库没有测试数据、权重、复现实验脚本或自动化基准，因此本仓库目前不能独立复现上述论文数值。

## 9. 当前已知阻塞、风险与限制

### 9.1 会直接影响运行的问题

1. **模型缺失**：仓库没有 `coarse.h5` 和 `fine.h5`，主推理无法完成。
2. **硬编码导入路径**：第 2 阶段把 `cwd` 固定为开发机 `/mnt/.../uq4d_scripts`，在新机器上可能导入错误或失败。
3. **外部程序不匹配**：脚本调用 `elastix`，仓库只带 Windows `.exe`；Linux 环境不可直接使用。
4. **目录名错误/依赖缺失**：脚本引用不存在的 `octave-tablicious-master`、`yamlmatlab-master`、`addMfile` 和多个未跟踪参数文件；虽然部分变量未进入当前 subprocess 路径，`Oct2Py()` 和 `addpath()` 仍可能在推理前失败。
5. **环境文件不可移植**：大量 `file://` 依赖指向原机器。
6. **设备固定**：预处理和合成都固定 `cuda:0`/`cuda`，没有显卡选择参数或 CPU 降级。

### 9.2 正确性与可维护性风险

1. `img_norm()` 仅乘以 `1/(max-min)`，没有减去最小值；输入不是零基线时不会真正归一化到 `[0,1]`，常量图还会除零。
2. 粗级循环在 `frame > 64` 时停止，但后续平滑和细级循环遍历全部帧；超过 65 帧时未估计部分保持零 DVF，语义不一致。
3. DICOM 像素固定乘 500 后转 `uint16`，没有根据原始 `RescaleSlope/Intercept` 或 BitsStored 进行完整动态范围验证。
4. UID 通过截断原 UID 和随机数字拼接，尚未用 DICOM 验证工具检查全局唯一性和合法长度。
5. 代码把参考头对象反复原地修改并复用；需要验证跨帧/跨层字段是否完整、Study/Series/FrameOfReference 关系是否符合预期。
6. 输出层使用 `-slice_index`；当 `slice_index=0` 时等于索引 0，而非最后一层，可能造成预期外的层顺序。
7. 第 1 阶段依赖 DICOM 文件名排序推断时间/层索引，没有使用 TemporalPositionIdentifier、InstanceNumber 等标签重新排序。
8. 聚类的簇排序和代表帧策略是启发式；中间簇直接取首个成员，不是均值或 medoid。
9. `ObtainSubMatrixGlobal()` 引用未实现的 `loss.PBM`，ROIErr/CNR/FWHM 只是占位。
10. 仓库没有单元测试、集成测试、CI、容器、正式 README、数据 schema 或错误恢复机制。

### 9.3 隐私、临床与部署边界

- 代码把 MR 号写回 `PatientName` 和 `PatientID`；日志也打印 MR 号和完整路径。使用真实数据前必须确定去标识化策略和日志权限。
- 当前输出是科研实现，不能仅依据论文结果直接进入诊断或治疗流程；需要本地数据验证、DICOM 合规验证、运动/解剖质控、故障病例处理、软件版本冻结和相应监管审查。
- `tmp_plot/`、MAT、NPZ 和临时 NIfTI 会显著增加磁盘占用，且包含患者图像，应纳入清理和访问控制。

## 10. 最低配置与模型规模：当前能确认到什么程度

- **能确认**：当前代码路径要求 NVIDIA CUDA GPU；粗/细输入分别为 `128³` 和 `224³`；论文在 RTX A6000/EPYC 9654/256 GB 上测速。
- **不能确认**：最低显存、最低 GPU 型号、最低 CPU 核数、最低系统内存、纯 CPU 是否可行、完整端到端耗时，以及两模型参数量。
- **原因**：权重和代表性测试病例缺失；代码未记录峰值显存/内存；论文给的是测试机而非最低配置。
- **建议测法**：取得权重后记录两个模型的 `count_params()` 和 H5 大小；对最大代表性病例分别测预处理、Elastix、粗级、DVF 平滑、细级、DICOM I/O 的时间，以及 `nvidia-smi` 峰值显存和进程峰值内存，再在不同 GPU/内存配置上重复。

## 11. 建议的工程化优先级

1. 补齐并校验权重、模型许可证和权重版本；建立一个匿名化最小示例病例。
2. 删除硬编码路径，把 GPU、Elastix、模型、临时目录和输出目录全部参数化。
3. 提供可移植 Conda/Docker 环境，并统一 TensorFlow/PyTorch 的 CUDA 组合。
4. 用 DICOM 标签而非文件名排序；增加输入 schema 和前置校验。
5. 修复归一化、超过 65 帧、负索引层序和 UID 生成问题。
6. 把两个顶层脚本拆成可测试函数；为数组形状、DVF 缩放、相位聚类、DICOM 几何和端到端最小病例增加测试。
7. 增加资源基准、失败日志、临时文件清理及临床质控报告。

---

**结论**：当前仓库已经包含从动态/静态 DICOM 预处理到两级形变合成和 DICOM 导出的完整研究型代码路径，也包含丰富的配准、指标和可视化辅助功能；但缺少模型权重、可移植环境、若干外部路径/组件和自动化验证，因此不能在全新机器上按 `runme.sh` 原样可靠复现。部署前应先解决第 9 节阻塞项，再以固定病例验证数值、资源、DICOM 合规性和论文指标复现情况。
